## Architecture Mindset

- **Separation of concerns** — UI renders; services decide; data persists. Mixing layers is how Friday deploys become Saturday postmortems.
- **API first** — Define the contract before the framework fanfare. Clients change; boundaries should not.
- **Modular design** — Small packages with sharp edges. Import graphs should read like a table of contents, not a conspiracy board.
- **Clean Architecture** — Dependencies point inward. Frameworks are plugins, not landlords.
- **SOLID** — Especially the *S*. God objects are just distributed technical debt with better naming.
- **Event-driven thinking** — Not everything needs a message bus. But side effects belong out of the request path.
- **Scalability** — Horizontal when possible, vertical when honest, premature when celebrated on LinkedIn.
- **Observability** — If you cannot trace it, you cannot fix it at 3 AM. Logs are not optional decoration.
- **Fail gracefully** — Timeouts, retries with backoff, and clear error surfaces beat silent corruption every time.
- **Boring infrastructure** — The best system design is the one your future self forgives.

## Engineering Rules

1. **Measure before you optimize.** Guessing is profiling with extra confidence.
2. **Code is read far more than it is written.** Name things like someone else pays rent on your codebase.
3. **Delete code without regret.** The best refactor often ends with fewer lines.
4. **Logs save lives.** Structured logs. Correlation IDs. Future-you sends thanks.
5. **Keep functions boring.** Clever code is a liability wearing a smirk.
6. **One source of truth.** Duplicate state is just a synchronization bug waiting for production.
7. **Defaults should be safe.** Opt-in to danger; never opt-in to sanity.
8. **Tests document intent.** A failing test is a specification that refused to lie.
9. **Ship thin slices.** Vertical cuts beat horizontal layers that never meet.
10. **Read the error message.** All of it. Yes, even the stack trace at the bottom.
